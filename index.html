Know which commit to review first.

Because “LGTM” isn’t a code review.

PR Risk Scorer reads a Git commit, scores its defect risk, shows exactly which signals drove the score, and leaves the decision with a person.

A final year project at SMIT, built on the ApacheJIT dataset. It prioritises review; it never decides a merge.

Reviewers can't read everything.

Small teams have limited review time. Some risky changes slip through while harmless ones get a long look, and junior developers' work is either rubber-stamped or over-checked at random.

Research calls the fix just-in-time defect prediction: estimate, at commit time, how likely a change is to introduce a bug. PR Risk Scorer turns that estimate into something a reviewer can use, and never into a bare 1 or 0.

From commit to decision in six steps

Every stage exists to turn a prediction into something a human can act on.

  1. Read the commit

    PyDriller pulls the change straight from Git.

  2. Extract features

    Size, dispersion, sensitive paths, tests, timing.

  3. Score it

    Weighted signals plus Logistic Regression, Random Forest and CodeBERT.

  4. Find evidence

    FAISS search for a similar past bug, only above a similarity threshold.

  5. Explain it

    Plain English from the score and signals. The raw diff is never sent.

  6. You decide

    Approve, request changes or escalate. Saved to an audit log.

One card per commit, with the reasons attached.

Not a wall of numbers. The score, each signal's contribution, the evidence and the explanation sit together, with the decision one click away.

  • Named signals, not an opaque probabilityEach point of the score traces to a signal you can read and argue with.
  • An honest "no match"If nothing in the index is close enough, it says so instead of forcing a nearest result.
  • Works without the internetWith no API key, or if the call fails, a local explanation is shown and the badge says so.

Runs on Linux, macOS and Windows

It’s plain Python, so it runs anywhere Python 3.11 or newer does. Pick your system.

# Linux
git clone https://github.com/funterpie/smit-final-project.git
cd smit-final-project
python3 -m venv .venv && source .venv/bin/activate
pip install -e .
prscore review HEAD~1
# macOS (Terminal)
git clone https://github.com/funterpie/smit-final-project.git

Honest note: it was built and tested on Ubuntu Linux. macOS and Windows should work, since nothing in the code is OS-specific, but they haven’t been tested yet. If something breaks, please open an issue on GitHub.

Your code stays local

Scoring, retrieval and the audit log all run on your machine.

The raw diff is never sent

The optional Groq explanation sees only the score, signal names and an evidence summary.

A person has the last word

Every decision, with the score and explanation shown, is saved to a local SQLite log.

What it doesn't do yet

Stated plainly, because a risk tool that overclaims gets ignored.

  • Trained and tested on Apache open-source data, which is Java-heavy. It may not transfer to other languages or codebases.
  • Labels come from the SZZ method, which can be noisy or misattribute a bug.
  • Author history is not computed in the live tool yet, so that signal is a placeholder.
  • The score is for prioritising review. It is not a calibrated probability and it does not prove a bug exists.
  • Retrieval is only as good as its curated index. A truly new bug pattern correctly returns no match.
  • Explanation quality has not been through a formal human-rated evaluation.
A reviewer, a risky commit and a Friday 5 p.m. deploy walk into a bar. The score said 80 out of 100. They approved it anyway.
Don’t be that reviewer. Check the card first.
